# Backlog

Requests collected along the way, with where they are planned.

| Request | Plan | Notes |
|---|---|---|
| Triple tap on the home screen to lock the phone | Stage 5 (gestures) | A normal app can only lock the screen through public APIs that the user enables once: an accessibility service (`GLOBAL_ACTION_LOCK_SCREEN`, Android 9+) or device admin (`lockNow`). Plan: an opt-in accessibility service with a clear explanation; if it is not enabled the gesture offers to set it up. Triple tap needs a short delay before single taps on empty space act. |
| Notification count badges | Stage 5, if wanted | Needs notification access (user grants it in Settings). |
| Icon shape for icons a pack does not cover, per-app icon override, dynamic clock icons | Done (Stage 4) | Shapes: Phone, Circle, Squircle, Rounded, Square. Themed icons (Android 13 monochrome). Pack style (iconback/iconmask/iconupon/scale). Per-app name and icon (from any pack or an image). Dynamic clocks use the AOSP clock metadata, so they only move for clock apps that declare it. |
| Real glass on the dock and over the wallpaper | Stage 5 | Launcher-managed wallpaper copy (normal apps cannot read the system wallpaper on Android 13). |
| Choose which app opens for "Wallpaper" (e.g. the phone maker's wallpaper app instead of the plain Android picker), or set the wallpaper inside the launcher | App choice done (0.4.8); in-launcher picker: Stage 5 | The launcher already asks Android for every app that handles "set wallpaper"; a maker's own wallpaper app often does not register for that, so only the plain picker shows. Plan: a "Wallpaper app" setting listing any installed app (no maker names hard-coded), plus an in-launcher picker (photos via the system photo picker, `WallpaperManager.setStream` with `SET_WALLPAPER`, a normal install-time permission) that also keeps the launcher's own copy for glass. |
| Pinch out on the home screen to show options (wallpaper, settings, widgets) | Stage 5 (gestures) | Same panel as long-press on empty space; Widgets joins it in Stage 3. |
| Resize widgets beyond what the app declares (e.g. Samsung weather to 1 column, as One UI allows) | Done (3.2) | Some Samsung widgets declare vertical-only resize (see docs/widget-sizes.md). Plan: a setting, "Resize any widget", off by default, that ignores the declared direction and minimum. |
| Long-press menu spacing to OneDepth's list pattern | Done (3.2, item menu) | OneDepth list (feedback screen): an inset column (8dp) of pill rows (48dp radius) with 20/12dp padding, 12dp icon-to-text, 4dp between rows. Panel radius = row radius + inset (about 30dp). Apply to the item menu and other lists. |
| Navigation bar area shows a black translucent strip | Attempted (3.2) | Translucent-bar flags from the device theme are now cleared and bars re-asserted transparent on every appearance change. If it persists, a screenshot is needed. The theme and window already ask for a transparent bar with no contrast scrim (status and nav). Need to see where it appears (home, drawer, light/dark) to find what draws it. |
| Remove the WidgetSizes debug log | Done (3.2) | Added in 3.1 to diagnose sizes. |
| Componentize the interface (one source per design element) | In progress (4.3: menu) | Done: the long-press menu (`ui/design/Menu.kt`), now used by home, folders, widgets and the drawer. Next: the search pill (drawer, widget picker, icon chooser), the bottom sheet frame (widget picker, edit app), pill list rows (settings, pack lists), the tool button (edit mode), settings cards and switch rows. |
